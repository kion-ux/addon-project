このファイルは **10 担当が並列で作業するときの共通の物差し** である。
四つの設計案を一本に統合し、矛盾は決着させた。ここに書いた数値が正典であり、

## 1. この作品の芯

**「磁力とは、金属が自分の意思で動いてしまうことだ」** — これを一枚の絵で読ませることに全ての予算を注ぐ。
優先順位は **① 遠景シルエット（兜の V／M と広い肩と長いマント）→ ② 撃発の一拍（0.06〜0.09 秒の急停止）→ ③ 磁力の三色（白＝瞬間 / 紫＝場 / 鋼＝動かされる物体）→ ④ 数値バランス** の順で、
下位のために上位を崩さない。動きは「腕を振る」のではなく **支持脚 → 腰 → 胸 → 肩 → 腕 → 手 → マント** の順に伝わる波として作り、
マントは常に一拍遅れる。エフェクトは加算だけで積まず、必ず通常合成の煙か塵を一層混ぜて質量を残す。

**擦り傷の規約**: 金属面（`helm` / `helm_dark` / `helm_crest` / `belt`）は `brushed` / `metal` の noise に加え、
`paint.py` の `panel_seam` 系で **上下方向 1px の細線を 3〜5 本、不等間隔** で入れる。等間隔にすると織物に見える。
擦り傷は `light` 色 α 60〜90、下地より必ず明るい側だけ。暗い傷は汚れであって傷ではない。

### 2-2. VFX の三色（**この三色以外を主役にしない**）

| 色の役割 | HEX | 合成 | 使う場所 | 寿命の上限 |
|---|---|---|---|---|
| **白 = 撃発の瞬間** | `#FFFFFF` | 加算 | 撃発キーの 1 枚だけ | **1〜3 tick** |
| **紫 = 力そのもの（不可視の場）** | `#B47CFF` → `#6B3AC8` → `#3A1C58` | 加算 | 芯・磁力線・リング・オーラ | 撃発から 10 tick 以内 |
| **鋼 = 磁力に動かされている物体** | `#B8C0CC` | **通常** | 破片・鉄片・瓦礫 | 制限なし |
| 塵・煙（質量の担保） | `#8E8A82` α0.35 | **通常** | どの見せ場にも必ず 1 層 | 0.9〜2.0 秒 |

技ごとの基調色（`TECHNIQUES[*]["colour"]`）は **縁の一段だけ** に使う。芯は必ず白へ寄せる。
tinting は 3 段グラデを必ず使う:

```
t=0.00 → (1, 1, 1)      白い芯
t=0.15 → 技の基調色      ここだけが技の個性
t=1.00 → 暗色 × α0      消え際
```

**加算と通常の使い分け**: 加算 = 光（芯・閃光・磁力線・リング）。通常 = 質量（破片・煙・塵・マント風）。
加算層は撃発から **10 tick 以内に全部消す**。それ以降の画面に残ってよいのは通常合成だけ。
加算だけで組むと昼の空で完全に飛ぶ。

## 4. アクションの規約

### 4-1. 拍の定義（**撃発だけ絶対秒で固定する**）

目は到達角ではなく **所要時間** で速さを読む。撃発を固定すれば L を変えても切れ味が落ちない。

| 系統 | L の範囲 | 予備 | 溜め | **撃発** | 伸び | 残心 |
|---|---|---|---|---|---|---|
| **軽 / 保持** | 0.60–0.86 | 0.18L | 0.10L | **0.06 秒固定** | 0.14L | 0.50L |
| **重** | 1.0–1.6 | 0.12L | 0.34L | **0.09 秒固定** | 0.12L | 0.40L |
| **必殺** | 2.4–3.2 | 0.08L | 0.42L | 0.10L **完全静止** → **0.08 秒撃発** | 0.16L | 0.24L |

**実キー時刻の式**（これを実装する）

| キー | 軽 / 保持 | 重 | 必殺 |
|---|---|---|---|
| `t_a` 開始（ニュートラル） | 0.00 | 0.00 | 0.00 |
| `t_b` 予備の底（逆方向へ引ききる） | 0.18L | 0.12L | 0.08L |
| `t_c` 溜めきり（**linear**） | 0.28L | 0.46L | 0.50L |
| `t_still` 完全静止の終わり（**同値2キー / linear**） | — | — | 0.60L |
| `t_d` **撃発 = オーバーシュート頂点**（**linear**） | `t_c + 0.06` | `t_c + 0.09` | `t_still + 0.08` |
| `t_e` 戻り着地（**linear**） | `t_d + 0.13` | `t_d + 0.20` | `t_d + 0.18` |
| `t_f` 残心終端（**linear**） | L | L | L |

- 軽は残心を 0.50L と長く取る。撃発が短い分、余韻で尺を稼がないと「動作が足りない」に見える。
- 重は溜めを 0.34L まで伸ばす。**溜めの長さがそのまま質量として読まれる**。
- 必殺は撃発直前に **完全静止 0.10L**。静止 → 撃発の落差が必殺の条件。現行 sphere にはこれが無い。
- `anim.py` の `EASE`（0.10 / 0.26 / 0.34 / 0.46 / 0.78）はこの表と矛盾する。**技側では使わない**。
  `beats()` は移動アニメ専用に残し、技は上の式で組む。

| `*Forearm` | +0.07 | 上腕の **1.4 倍の角速度**で追い越す（しなり） |
| `*Hand` | +0.09 | 遅れ振り ±20° |
| `neck` | +0.06 | **逆方向 0.4 倍**（頭が置いていかれる） |
| `head` | +0.10 | 追いつく |
| `cape0` / `1` / `2` | +0.06 / +0.10 / +0.14 | 起点は **`t_d`** |
| `cape3` / `4` / `5`（L/R） | +0.18 / +0.22 / +0.26 | L と R は **逆位相**、Y も ±(3+3i)° |
| 遊脚 | +0.06 | 反対向き |

**`neck` と `*Shoulder` は現行 15 技で一度も使われていない。ここが無いから全技が「腕だけ」に見える。**
どの技も最低限 `body` / `chest` / `neck` / `*Shoulder` / `*Forearm` / `cape*` を触ること。

### 4-5. マントの振り（`gen_anim_tech.cape()` の作り直し）

**現行の二大バグ**

- ピークが `lag*(i+1) + length*0.22` の**固定割合**で、撃発と無関係。
  repulse は cape0 が 0.249 秒でピークなのに撃発は 0.36 秒 → **マントが腕より 0.11 秒先に動く**。
  sphere は cape0 ピーク 0.784 秒で撃発 2.28 秒 → **クライマックスでマントが完全に死ぬ**。
- cape0-3 が親子チェーンなのに amp が末端ほど大きい（`0.55 + 0.15*i`）。
  46° × (0.55+0.70+0.85+1.00) = 先端実効 **約 143°** で体を突き抜ける。

**新しい仕様**

```
cape(profile, length, strike, segments=6)
    ピーク時刻     = strike + lag * (i + 1)
    戻り時刻       = ピーク + length * 0.30
    段ごとの amp   = peak * (1.00, 0.86, 0.74, 0.62, 0.52, 0.45)[i]   ← 減衰
    累積合計       = 70° を上限に正規化（超えたら全段を一律スケール）
    裾 L/R         = 同じ X 角に、Z ±(6 + 5i)·sin(t)、Y ±(3 + 3i)°
```

| profile | lag (秒) | peak (°) | back (°) | 使う技 |
|---|---|---|---|---|
| `whip` | 0.06 | 46 | 8 | 前へ踏み込む技 |
| `flare` | 0.08 | 62 | 12 | 両手を掲げる技 |
| `settle` | 0.05 | 18 | 4 | 動きの小さい技 |
| `swirl` | 0.10 | 38 | −10 | 回る技（巻き込んでから開く） |

移動側（`gen_anim_loco.py`）の `cape_move` は swing に上限が無く、疾走時に 90° を越えて裏返る。
**`math.clamp(expr, -8, 62)` で締める。** Y / Z が全段ハードコード 0 になっているのも直し、
L / Z を `±(6 + 5i)·sin(t)` の左右逆位相にする。

### 4-6. `catmullrom` と `linear` の境界

判定は 3 つだけ。

1. **通過点か到達点か。** 通過点 = `catmullrom` / 到達点（撃発・接地・保持の開始と終了・最終ニュートラル）= `linear`。
2. **前後のキー間隔が 2 倍以上違うキーは `linear`。** `catmullrom` は等間隔前提で、
   0.06 秒の撃発を 0.30 秒の溜めと繋ぐと接線が暴走する。**撃発の直前キーと撃発キーの両方**を `linear` に。
3. **同値が 2 キー続く保持区間は両端 `linear`。** 曲線だと次キーの傾きが漏れて保持が崩れる。

| 区間 | 補間 |
|---|---|
| 予備・溜め | `catmullrom` |
| **撃発の直前キー・撃発キー** | **`linear`** |
| オーバーシュート頂点 | `catmullrom` |
| **戻り着地** | **`linear`** |
| 残心の中間 | `catmullrom` |
| **終端** | **`linear`** |
| 瞬間切替 | `anim.step()` の pre/post 分割 |

`gen_anim_tech.py` は現在 **`hold` / `step` を import すらしていない**ので全キーが `catmullrom`。
barrier の 0.42 と 0.86 の保持キーが 1.10 のニュートラルへの傾きを拾い、**0.86 の時点で既に構えが解け始めている**。
crush の握り込みも角が丸まって「握った瞬間」が無い。撃発キーと保持キーを `hold()` に置き換える。

### 4-7. scale チャンネル（squash）

`build()` は `"s"` を受けるのに **15 技すべてで 0 回**しか使われていない。
撃発の 1〜2 フレームだけ潰すと衝撃が乗る。

| 系統 | 対象 | 撃発キーの scale | 戻し |
|---|---|---|---|
| 軽 | `chest` | `[1.00, 0.94, 1.06]` | `t_e` で `[1,1,1]` |

| 一人称 | `core` | 溜め `0.72` → 撃発 `1.35` → 0.10 秒で `1.00` | — |

## 5. VFX の規約

### 5-1. 層の重ね方（原則）

1. 予兆（通常 or 弱い加算） → 2. 溜め極大（加算） → 3. **撃発 = 白 1 枚だけ**（加算・1〜3 tick）
→ 4. 波 / リング（加算・`age^0.45` で減速展開） → 5. 破片（**通常**） → 6. 塵・煙（**通常**、最後まで残す）

- 撃発の tick に **加算層を 2 種類以上置かない**。白が濁って全技が同じに見える。
- **どの見せ場にも通常合成の煙か塵を必ず 1 層**。
- 加算層は撃発 +10 tick で全消し。以降に残るのは通常合成のみ。

## 6. 一人称 / 三人称の描き分け

**大原則**: **拍の秒数（`t_a`〜`t_f`）は三人称と完全一致させ、割り当てるチャンネルだけ変える。**
撃発 tick を共有し、一人称は shake と core の scale、三人称は pose 差し替え、パーティクルは共通の locator から出す。

| | 三人称 | 一人称 |
|---|---|---|
| **主役** | 腰の捻り（±30°）とマント | `core` の scale と `shard` の半径 |
| **見せるもの** | シルエット・輪郭・翻り | 視界の縁で動く圧、手元の情報 |
| **`root`** | — | 画面内移動は抑える（position ≤ 3.0 / rotation ≤ 40°）。撃発 0.06 秒で −1.2 前、戻し 0.22 秒 |
| **`field`** | — | 回転を 待機 55°/s → 溜め 900°/s → **撃発の瞬間 120°/s へ落とす**。加速ではなく**急停止**が「掴んだ」感になる |
| **`core`** | — | 溜めで scale 1.0 → **0.72（吸い込み）**、撃発の 1 キーで 1.35、0.10 秒で 1.0 |
| **`shard0-2`** | — | 位相を 0/120/240 でなく **0 / 104 / 248** に崩す。溜めで半径 −3.0 内へ、撃発で +6.0 外へ。各 shard に **0.02 秒ずつ遅れ** |
| **指** | — | 握り **0.08 秒** / 開き **0.12 秒**（拍とは別系統の細部） |
| **VFX で出すもの** | 全層 | 手元 0.3〜0.8m の芯（size ≤ 0.15、加算、life ≤ 0.15 秒）／3m 以遠のリング・磁力線／`fog`／`camera.fade` |
| **VFX で出さないもの** | — | **カメラから 0.3〜2.5m の煙・塵・破片**。ここに通常合成の大きい粒を置くと視界が全潰れになる → **三人称専用** |
| **shake** | 周囲へ `positional` | `rotational`、小さく高頻度（0.08〜0.18） |
| **pose hold** | 22 → **26 tick 以上**（§4-2 の表）で構えを読ませる | — |

**実装**: 三人称の `animation.marvel.tech.*` には全層、一人称の `animation.marvel.fp.*` には
**芯と閃光だけ**を別途 `particle_effects` で持たせる。**現状 fp 側の `particle_effects` は 0 件**で、
一人称に固有の絵が一切ない。

**一人称の act が発火しない不具合**: tech アイテムは `itemUse`（単発、`main.js:62`）で発動し、
`use_modifiers` は food のみ（`gen_bp.py:253`）。`fp.tech` コントローラは `query.is_using_item` で
act へ遷移するので、0.6 秒の技アニメが実質再生されない。
→ **tech アイテムに `minecraft:use_modifiers {use_duration: 0.7}` を付け、`itemStartUse` で発動する。**

**pose が idle/walk と加算される不具合**: `form_controller` の各 state は `["idle","walk","pose"]` を
並べるだけ（`gen_anim_loco.py:568`）なので、歩きながら撃つと腕の振りが技のポーズに足し算されて形が壊れる。
→ **tech clip に `override_previous_animation: true` を付ける**（`clip()` は既に `override` 引数を持つが `tech()` が渡していない）。
